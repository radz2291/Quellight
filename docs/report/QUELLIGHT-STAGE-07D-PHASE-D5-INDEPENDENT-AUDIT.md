### 4.1 FINDING B-1 (Blocking): deep purge fails for ceremony-created meaning — FK ordering

- **Reproduction (deterministic, on the frozen tree, disposable store):** a claim created through the product's NORMAL path (agent proposal → awaiting_decision → user confirm) carries `qlt_claim.proposal_id = qlt-…` (FK `REFERENCES qlt_proposal(id)`). A plus-meaning deletion tombstones it — the D1 tombstone null-set does NOT include `proposal_id`, so the reference survives. The subsequent typed deep purge (`confirmation: 'purge'`) throws a raw `Error: FOREIGN KEY constraint failed` (`ERR_SQLITE_ERROR`) inside `purgeConversation`'s transaction.
- **Root cause:** the frozen purge step order (`QLT_D2_PURGE_STEP_ORDER`, `d2-contract.ts`) deletes `qlt_proposal` rows (step 5) BEFORE the originating subject tombstone rows (step 6), while `qlt_claim`, `qlt_commitment` (and its `normative_basis_proposal_id`), and `qlt_open_loop` each declare `proposal_id … REFERENCES qlt_proposal(id)` (migration shapes, `migrations.ts` lines 117/138-139/165/391/440-441/491/614) and `PRAGMA foreign_keys = ON` is set by `createSharedWorldSqlite`. The order is FK-invalid for every ceremony-created record — which is the product's normal meaning path (the UI creates meaning only through proposals/ceremony).
- **Impact:** the deep purge — a required D2 capability with frozen semantics — is functionally broken in its principal scenario (plus-meaning deletion + purge). It fails CLOSED: the transaction rolls back, no partial deletion occurs, no receipt is written, nothing is over-deleted, and no false success is claimed (the route maps the raw error to the stable `QLT_PURGE_INCOMPLETE`). No data-safety violation occurs; a required feature does not work.
- **Why committed evidence missed it:** the D4 attempt-2 proof has no purge point; `verify:browser-d2` purges a conversation-only deletion (no proposals/subject rows deleted — passes); `verify:d2` purges only meaning seeded through the direct user verbs (`createClaim`/`createCommitment`/`createOpenLoop`), which leave `proposal_id` NULL — see finding H-1.
- **Not repaired** (mandate: report and stop).
