# Quellight Stage 07D Phase D4a — Proof Contract Amendment 1 (Determinism at the Product Boundary)

> **Class:** Standalone contract amendment. Amends the D4 proof
> contract `quellight.stage07d.d4.proof-contract@1` →
> **`quellight.stage07d.d4.proof-contract@2`**. The original Phase 0
> freeze (`59bb43ad`) and the historical preparation report are NOT
> rewritten; this amendment records the delta. Committed BEFORE any
> dependent executable change. **This amendment authorizes nothing; no
> provider, credential, operator data, `.pi/`, `.quellight-data`, or
> scenario file was or is accessed; D4 remains NOT executed.**

## 1. Finding

The @1 preparation report carried the limitation:

> A7's live trigger depends on the model's key choice by design.

That makes a required structural proof depend on nondeterministic model
discretion — the failed Q6 pattern. The audit below shows two more
required conditions with the same defect, plus one vacuous pass. The
accepted product principle is applied: model discretion is a real-use
OBSERVATION; required state transitions must have a deterministic
owner-governed path; exact wording, autonomous capability selection, and
model-selected semantic keys must never decide whether the structured
proof can complete.

Surface audit (repository reality, no product changes made or needed):
commitment-kind proposals are created ONLY by the agent draft
capability; the deterministic conflict detector runs ONLY at the owner
decision boundary `confirmProposal` (conflict-surface
`ensureChallenge` is reachable from nowhere else); the governed plan's
ceremony inventory is frozen at exactly thirteen ops and exposes no
owner proposal-draft action. The amendment therefore works WITHIN the
frozen inventory: the challenge class is proven deterministically at
the real user boundary offline (new permanent control N-D4-P-23), and
in the live session its full exercise is a must-behave-correctly
OBSERVATION whose absence can never fail an otherwise valid session.

## 3. Semantic changes

1. **Outcome `failed-scenario-behavior` and code `QLT_D4_SCENARIO_BEHAVIOR` are REMOVED.** No required point may fail because the model did not act. Infrastructure-only failures keep `failed-infrastructure`.
2. **@1's A3 truthfulness caveat is resolved** — the structured session can no longer seal `failed-scenario-behavior` when no proposal is drafted; the no-agent-canonical proof is store-attribution-based and model-independent.
3. **A9's removal goes through the governed plan** (`act.removeRecord`) instead of the retention store service — the same user boundary the product UI uses.
4. **The transcript marker is imported from the context contract** (`QLT_CONTEXT_BLOCK_OPEN`) instead of a harness-local literal.
5. **Optional model observations** are receipt-detail facts under the reserved vocabulary `QLT_D4_OBSERVATION_DETAIL_KEYS` (`modelProposalObserved`, `ceremonyObservation`, `conflictClassExercised`, `pendingProposalObservation`). They are structural (no content) and can never gate a required check.
6. **Contract identity** becomes `quellight.stage07d.d4.proof-contract@2`; receipts and evidence record the producing mapping.

## 4. Credential boundary wording (reconciled)

Repository reality: the pinned provider credential resolves through the
environment variable `OLLAMA_API_KEY` OR the owner-designated
authentication file (the Q6 live precedent). The owner's configured
supported path is the authentication file. The authorization text no
longer hardcodes the environment variable: it names the
owner-designated provider credential source, handled presence-only,
held in memory for the pinned transport, never printed, hashed,
persisted, reported, or copied into the proof workspace. The credential
is NOT read during this amendment.

## 5. Added permanent controls (extend N-D4-P-1..18 with 19–24)

- **N-D4-P-19** — a complete synthetic ledger with ZERO model observations seals `passed` (no required point needs model behavior).
- **N-D4-P-20** — the same ledger WITH observation details seals identically; adding/removing observations never changes the verdict.
- **N-D4-P-21** — an unknown (non-required) check id is refused by the ledger — invented or model-proposed "evidence" cannot enter.
- **N-D4-P-22** — static: the classification covers every required check; no required check classifies as a model observation; the scenario-behavior outcome/code no longer exist anywhere.
- **N-D4-P-23** — REAL composition, offline: direct Save crosses the real governed boundary; the deterministic conflict class is triggered by an intentional owner confirmation at the real user boundary (the proposal created through the production store service the capability itself wraps — never raw SQL); refusal + challenge + quiet dismissal with user-only authority; the standing commitment unchanged; a refused proposal creates no canonical record.
- **N-D4-P-24** — static: every harness governed action id is declared by the plan; no fixture trigger phrases; no required condition keyed on model wording, tool choice, or hidden reasoning.

## 6. Bounds

Unchanged and re-affirmed: one session; ≤ 45 minutes; 5 user turns; ≤ 20
provider requests; ≤ 2048 output tokens per request; ≤ 120 s per-turn
deadline; zero retries; no fallback. The amendment adds no turns and no
provider requests (expiry seeding uses governed owner actions offline of
the turn loop).
